# להוציא את הפרסום מהמחשב בבית

## למה זה הדבר החשוב

היום מנוע הפרסום הוא חלון שחור על מחשב אחד שחייב להישאר דולק. זה עובד —
אבל זה גם הדבר היחיד שעוצר את זה מלהיות מוצר: **כל לקוח צריך מחשב משלו,
דולק, עם הפרופיל שלו.** לקוח שלישי זה כבר שלושה מחשבים, ולקוח שסוגר את
המחשב בלילה מקבל סבב שלא יצא.

המסמך הזה מחליף את המחשב הזה במכולה (container) שרצה בענן.

**מה לא משתנה:** אותו קוד, אותה לוח בקרה, אותה התנהגות. ה-worker לא יודע
איפה הוא רץ. מה שמשתנה זה איפה הוא רץ ואיפה הפרופיל שמור.

---

## הסיכון האמיתי, לפני שמתחילים

**כתובת ה-IP.** החשבון שלך מתחבר לפייסבוק מבאר שבע, מבית, כבר שנים. שרת
בענן הוא כתובת של חוות שרתים — ופייסבוק יודעת להבחין. זה הדבר היחיד שסביר
שיהפוך סשן עובד לבקשת אימות.

אין לי דרך להבטיח שזה לא יקרה, ולא אמכור לך ביטחון שאין לי. אבל יש שלושה
דברים שמקטינים את זה משמעותית, וכולם כבר בנויים כאן:

1. **להעביר את הפרופיל הקיים, לא להתחבר מחדש.** התחברות טרייה היא מה
   שמפעיל בדיקות אבטחה. סשן קיים שממשיך מכתובת חדשה נבלע הרבה יותר בקלות.
2. **שעון ישראל בתוך הדפדפן.** מכולה רצה על UTC. הדף יכול לקרוא את השעון
   של עצמו בשורה אחת, וסשן שאומר UTC בזמן שהחשבון אמר Asia/Jerusalem במשך
   שנים הוא הבדל בחינם. הוא נסגר אוטומטית.
3. **פרוקסי ביתי, אם צריך.** אם בכל זאת מגיעה בקשת אימות — מנתבים את
   הדפדפן דרך כתובת ביתית בישראל. זה עולה כסף, ולכן זה תוכנית ב' ולא א'.

---

## מה צריך

- שרת עם Docker. VPS קטן מספיק (2 ליבות / 2GB). **ככל שקרוב יותר לישראל,
  טוב יותר.**
- קובץ `.env.local` — אותו אחד שכבר יש לך.
- **הפרופיל מהמחשב הקיים.** זה החלק החשוב.

---

## שלב 1 — לקחת את הפרופיל מהמחשב

במחשב שבו זה עובד היום, **כשה-worker סגור**:

```
%USERPROFILE%\.hapitaron-social\facebook-profile
```

לדחוס את כל התיקייה. זו הזהות: העוגיות, האחסון המקומי, ומזהה המכשיר
שפייסבוק זוכרת. **בלי זה השרת יצטרך להתחבר מחדש, וזה בדיוק מה שאנחנו
מנסים להימנע ממנו.**

## שלב 2 — להרים את המכולה

```bash
git clone <הריפו> && cd ANX-
cp /path/to/.env.local .
docker compose -f worker/docker-compose.yml up -d
docker compose -f worker/docker-compose.yml stop
```

## שלב 3 — להכניס את הפרופיל פנימה

```bash
docker run --rm -v anx-_fb-profile:/data -v "$PWD":/backup alpine \
  sh -c "rm -rf /data/facebook-profile && unzip -q /backup/facebook-profile.zip -d /data"
docker compose -f worker/docker-compose.yml up -d
docker compose -f worker/docker-compose.yml logs -f
```

בלוג צריך להופיע `בדיקת חיבור לפייסבוק: ...` ואחריו מצב מחובר. בלוח הבקרה
יופיע worker חדש בשם `worker@cloud`.

## שלב 4 — לכבות את המחשב בבית

רק אחרי שהענן פרסם בהצלחה. **אל תריץ את שניהם במקביל** — שניהם ימשכו
מאותו תור ויריבו על אותן שורות. ה-worker מזהה כפילות בשם, אבל שני שמות
שונים הם שני עובדים לכל דבר.

---

## אם פייסבוק מבקשת אימות

זה התרחיש שהוכן מראש.

1. **קודם כול — פשוט לאשר.** לוח הבקרה מציג את מסך האימות ומאפשר להזין את
   הקוד מהטלפון. אם זה עבר, סביר שזה חד-פעמי: פייסבוק ראתה כתובת חדשה
   ושאלה. אחרי אישור אחד היא בדרך כלל זוכרת.
2. **אם זה חוזר** — הכתובת היא הבעיה. אז, ורק אז, פרוקסי ביתי בישראל.
   ב-`worker/docker-compose.yml` יש שלוש שורות מסומנות בהערה; להסיר את
   ההערה ולמלא. אין צורך לשנות קוד.

---

## למה מכולה אחת לכל לקוח

לא בשביל סדר — בשביל **הפרדה**. סשן פייסבוק הוא תיקייה. שתי מכולות, שתי
תיקיות, ושום דרך שלקוח אחד יראה את החשבון של אחר. להוסיף לקוח זה להעתיק
את הבלוק ב-compose ולשנות שלושה דברים: שם השירות, שם ה-volume, ו-
`SOCIAL_WORKER_NAME`.

`shm_size: 1gb` אינו קישוט: ברירת המחדל של Docker היא 64MB, ודפדפן קורס
באמצע העלאת וידאו בלעדיה — והקריסה נראית בדיוק כמו פייסבוק שדוחה את הפוסט.
