# מערכת SEO — "הפתרון המבריק"

מערכת תוכן אוטומטית שמייצרת מאמרים בעברית וברוסית לאזור הדרום, מריצה עליהם בדיקות
איכות, ומעבירה אותם לתור אישור ידני. **שום דבר לא מתפרסם בלי שמישהו יאשר אותו.**

הדשבורד: **`/crm/seo`** (אותה התחברות של ה-CRM).
העמודים הציבוריים: **`/articles`** ו-**`/articles/<slug>`**.

## מה המערכת עושה

| שלב | מה קורה | איפה בקוד |
| --- | --- | --- |
| 1. מחקר | קוראת שאילתות אמיתיות מ-Google Search Console, מסמנת הזדמנויות | `src/lib/seo/server/gsc.ts` |
| 2. תכנון | בוחרת 2 נושאים לשבוע — קודם מביקוש אמיתי, אחר כך ממאגר נושאים | `src/lib/seo/planner.ts` |

## הקמה

### 1. מסד הנתונים

הריצו ב-Supabase: **SQL Editor → New query** → הדביקו את `supabase/seo-schema.sql` → **Run**.

הקובץ בטוח להרצה חוזרת (idempotent) ולא נוגע באף טבלה קיימת. הוא יוצר שש טבלאות
(`seo_articles`, `seo_article_versions`, `seo_keywords`, `seo_runs`, `seo_logs`,
`seo_settings`), כולן נעולות ב-Row Level Security.

חריג יחיד ומכוון: מאמר בסטטוס `published` קריא גם למפתח ה-anon — זה *עמוד אינטרנט
ציבורי*. טיוטה, מאמר שנדחה או מאמר שממתין לאישור **אינם** קריאים למפתח הציבורי, ולכן
תוכן לא מאושר לא יכול להגיע לאתר גם אם יש באג בשאילתה.

### 2. משתני סביבה

כולם **בצד השרת בלבד** — אף אחד מהם לא מתחיל ב-`NEXT_PUBLIC_`, ולכן אף אחד לא נשלח
לדפדפן. הגדירו אותם אצל המאכסן (ב-Vercel: Project → Settings → Environment Variables).

| משתנה | למה זה נחוץ | מה קורה בלעדיו |
| --- | --- | --- |
| `SUPABASE_SERVICE_ROLE_KEY` | כדי שהמחזור המתוזמן יוכל לכתוב מאמרים בלי משתמש מחובר | המחזור לא רץ. הדשבורד מציג "לא מוגדר" |
| `ANTHROPIC_API_KEY` | מנוע הכתיבה | אין יצירת מאמרים |
| `CRON_SECRET` | הסוד שהתזמון השבועי מציג | המחזור האוטומטי סגור; רק אדמין מחובר יכול להריץ |
| `GSC_SITE_URL` | הנכס ב-Search Console | אין נתוני ביצועים; הנושאים נבחרים מהמאגר המתוכנן |
| `GOOGLE_CLIENT_ID` | OAuth | כנ"ל |
| `GOOGLE_CLIENT_SECRET` | OAuth | כנ"ל |
| `GOOGLE_REFRESH_TOKEN` | גישת קריאה לנכס | כנ"ל |

**האתר עולה ועובד גם בלי אף אחד מהם.** כל מסך בדשבורד שתלוי באינטגרציה חסרה מציג
"לא מחובר" ומפרט בדיוק איזה משתנים להוסיף — ולא מציג אפסים שנראים כמו נתונים.

### 3. חיבור Google Search Console

1. ב-[Google Cloud Console](https://console.cloud.google.com): צרו פרויקט והפעילו
   **Search Console API**.
2. **APIs & Services → Credentials → Create Credentials → OAuth client ID**, סוג
   **Web application**. הוסיפו `https://developers.google.com/oauthplayground` ל-Authorized
   redirect URIs.
3. ב-[OAuth Playground](https://developers.google.com/oauthplayground): בהגדרות (⚙️) סמנו
   *Use your own OAuth credentials* והדביקו את ה-Client ID וה-Secret. בחרו את ה-scope
   `https://www.googleapis.com/auth/webmasters.readonly`, אשרו עם החשבון שיש לו גישה לנכס,
   ולחצו **Exchange authorization code for tokens**.
4. העתיקו את ה-**Refresh token** אל `GOOGLE_REFRESH_TOKEN`.
5. `GSC_SITE_URL` — בדיוק כפי שהנכס מופיע ב-Search Console, כולל הסלאש בסוף
   (`https://example.co.il/`), או `sc-domain:example.co.il` לנכס דומיין.

### 4. תזמון שבועי

התזמון יושב ב-`.github/workflows/seo-weekly.yml` ורץ בימי ראשון ב-04:10 UTC.
תחת **Settings → Secrets and variables → Actions** הגדירו:

- `SEO_APP_ORIGIN` — הכתובת של האתר החי, למשל `https://your-app.vercel.app`
- `SEO_CRON_SECRET` — אותו ערך בדיוק כמו `CRON_SECRET` באפליקציה

> **למה GitHub Actions ולא Vercel Cron:** Vercel Cron שולח רק GET, ו-route handler מסוג
> GET מפיל את `output: export` — מה שהיה שובר את ה-deploy הקיים של GitHub Pages
> (`.github/workflows/deploy.yml`). לכן `/api/seo/run` הוא POST בלבד, והתזמון חי ב-Actions.
> בונוס: זה עובד על כל מאכסן, לא רק Vercel.

אפשר גם להריץ ידנית: **Actions → Weekly SEO content cycle → Run workflow**, או מהכפתור
"הרץ מחזור עכשיו" ב-`/crm/seo`.

## עשר בדיקות האיכות

כל הבדיקות **דטרמיניסטיות** — ניתוח טקסט ומבנה, בלי קריאה שנייה למודל. מודל שבודק את
עצמו הוא לא בדיקה, הוא אותו ניחוש פעמיים; ובדיקה דטרמיניסטית נותנת את אותה תשובה על
אותה טיוטה בכל פעם, כך שאפשר להסביר דחייה במילים קונקרטיות.

| # | בדיקה | מה היא תופסת |
| --- | --- | --- |
| 1 | התאמה לאזור הדרום | עיר מחוץ לאזור השירות, גם כהשוואה |
| 2 | איכות שפה | מאמר "ברוסית" שנכתב בעברית, או טקסט קצר מדי |
| 3 | דיוק מחירים | **כל** מספר שקלים שלא מופיע במחירון המאושר |
| 4 | מקוריות וערך | פסקאות חוזרות, מבנה שטוח, פחות משתי שאלות ותשובות |
| 5 | כפילות | חפיפת טריגרמות מעל 30% מול תוכן קיים באותה שפה |
| 6 | כותרות ותגיות | H1 יחיד, H3 אחרי H2, אורכי Title ו-Description |
| 7 | קישורים פנימיים | נתיב שלא קיים, או הצפת קישורים |
| 8 | כוונת חיפוש | ביטוי המטרה חסר בכותרת או בגוף |
| 9 | הבטחות לא מבוססות | "מתחייבים", "100%", "הזול ביותר", וכו' |
| 10 | הנחיות Google | הצפת מילות מפתח, Description שזהה ל-Title, מחיר בלי הסתייגות |

**ארבע בדיקות חוסמות פרסום** ולא ניתן לדלג עליהן בשום מצב, גם אם הציון גבוה:
אזור שירות (1), דיוק מחירים (3), הבטחות (9) וקישורים (7). מאמר שנכשל באחת מהן
אפילו לא מגיע לתור האישור.

הציון (0–100) הוא **ציון פנימי של המערכת, לא ציון של גוגל** — וכך הוא מסומן בכל מקום
שבו הוא מוצג.

הרצת הבדיקות:

```bash
npm run test:seo     # 23 בדיקות על מנוע האיכות והתכנון
```

## מה המערכת לא תעשה

החלטות שנאכפות **מבנית** ולא בעזרת בקשה מנומסת למודל:

- **לא מפרסמת לבד.** נקודת הקצה `/api/seo/run` יכולה לכתוב רק `draft` או
  `pending_approval`. הפונקציה היחידה בכל הקוד שכותבת `published` היא `publishArticle`
  ב-`src/lib/seo/client.ts`, ומגיעים אליה רק בלחיצה בתור האישור.
- **לא ממציאה מחירים.** מנוע הכתיבה מקבל גיליון עובדות שנבנה מ-`src/lib/seo/config.ts`
  ואין לו אינטרנט, כלים או מקור אחר. מחיר שלא במחירון נחסם בבדיקה 3.
- **לא ממציאה ביקורות, מספרי לקוחות או אחוזי הצלחה.** אין נתונים כאלה בקונפיג, ולכן אין
  מאיפה לקחת אותם.
- **לא כותבת על עיר שאינה באזור השירות.** ארבע הערים הן גם `CHECK` במסד הנתונים.
- **לא מתרגמת.** הגרסה הרוסית נכתבת מהנושא, בקריאה נפרדת, עם מחקר ביטויים עצמאי —
  כי דובר רוסית בישראל מחפש "химчистка дивана", לא תעתיק של "ניקוי ספות".
- **לא מריצה XSS.** גוף המאמר נשמר כבלוקים מובנים (`jsonb`), לא HTML ולא Markdown, ומוצג
  כ-text nodes של React. אין `dangerouslySetInnerHTML` באף מקום בנתיב הפרסום.
- **לא מבטיחה אינדוקס או מיקום בגוגל**, ולא מציגה נפחי חיפוש או נתוני תחרות — Search
  Console לא מספק אותם.

## מה חסר כדי שזה ירוץ

המערכת בקוד ועוברת build, typecheck ובדיקות. כדי שהיא תתחיל לייצר תוכן בפועל צריך:

1. להריץ את `supabase/seo-schema.sql`
2. `ANTHROPIC_API_KEY` + `SUPABASE_SERVICE_ROLE_KEY` + `CRON_SECRET`
3. `SEO_APP_ORIGIN` + `SEO_CRON_SECRET` כ-secrets ב-GitHub
4. (רשות, מומלץ) ארבעת המשתנים של Search Console — בלעדיהם הנושאים נבחרים מהמאגר
   המתוכנן במקום מביקוש אמיתי

**לא בדקתי מול API אמיתי** — אין בסביבה הזו מפתח Anthropic, פרויקט Supabase או נכס
Search Console. מה שכן נבדק: build (רגיל וסטטי), typecheck, ו-23 בדיקות על מנוע האיכות
והתכנון. הקריאה הראשונה ל-`/api/seo/run` בסביבה אמיתית היא הבדיקה שנותרה.
